# 人类作答记录与统计口径

## 保存的信息

研究主机的 `runs/my-study/` 保存：

- 受试者编号、任务分配及顺序、图片／文本条件、阅读确认和退出时间。
- 每次作答的任务 ID、开始与结束时间、原生正误／得分、终止原因、原生决策步数、用时及计时来源、运行软件版本。
- 每一步动作、请求编号、服务端收到动作的时间及回执，用于核对操作与处理断线重传。
- 游戏窗口截图或文本盘面，以及主机私有的原生状态和判分证据。
- 固定任务快照与研究协议。邀请码、登录会话在数据库中只保存摘要；管理员口令保存在权限600的独立文件中。

研究记录不要求姓名、邮箱，不采集摄像头或麦克风。应用仅使用 IP 做内存中的登录限速，不把 IP 加入研究结果或导出；Cloudflare 的网络日志由其独立配置管理。停止服务不会删除研究记录。

## 每题与每次尝试

管理页的“逐题明细”以 **受试者 × 分配题目** 为一行，显示正误、秒数、步数、游戏项目、具体游戏、难度、界面和状态。

正式评分后不能重做。如果一次环境中断后显式重启，同一题最终只计入首个正式评分结果；中断尝试仍保存在“尝试记录 CSV”和完整 JSON 中。未开始、作答中、退出未作答、环境中断均保留为未评分，不当作答错或零用时。

## 正误、时间与步数

- **正误**：按原生目标是否达成判定。预算耗尽、主动结束但未完成目标是错误；环境故障或退出当前研究是未评分。
- **用时**：从服务端首个盘面就绪至服务端确定结果的墙钟时间。包括思考、操作和断线时间；不包括原生游戏启动、题间休息、明确暂离和结束后的进程收尾。超时题记该研究的时间上限。新作答采用单调时钟，避免系统时钟调整影响。
- **旧记录**：如果只有开始／结束时间戳，则展示两者差值并标记 `legacy_wall_clock_estimate`；可能包含旧实现的收尾时间。不能确定的时间保持空值，不补零。服务崩溃后无法确定实际结束时刻的未评分尝试不会伪造精确时长。
- **步数**：原生结果中的决策数，按原动作协议计数；无效动作、撤销等也可能消耗决策。相同请求编号的网络重传不增加步数。

## 汇总

支持全部受试者或单个受试者，图片／文本单独或合计；按六个游戏项目、具体游戏（Fifteen、Net、Untangle分别列出）、简单／中等／困难、项目×难度、题目汇总。

每份已评分作答等权：

```text
正确率 = 正确作答数 / 已评分作答数
平均用时 = 已评分且有有效用时的秒数之和 / 有效计时份数
平均步数 = 已评分且有有效步数的步数之和 / 有效步数份数
```

“所有已评分题”均值包括正确、错误和超时；“仅答对题”均值只包含正确结果，单独列出。每个均值都附有自己的有效样本数；缺失值不填0，空组均值为null（页面显示“—”）。统计采用作答层面的微平均，不是先算类别平均再对类别等权。不同受试者答同一道题各计一份。

## 导出

| 文件 | 内容 |
|---|---|
| 全部逐题 CSV：`/api/admin/results.csv` | 每位受试者的每道分配题一行；correct为1／0，未评分为空；时间单位秒 |
| 全部汇总 CSV：`/api/admin/summary.csv` | 全体／单人、界面及各分类汇总，包含均值和分母；accuracy为0到1的小数 |
| 尝试记录 CSV：`/api/admin/export.csv` | 保留每次attempt，包括中断尝试及其计时来源 |
| 完整 JSON：`/api/admin/export.json` | 协议、参与者分配、尝试、动作时间、逐题结果及统计口径与汇总 |

CSV 导出是全量数据，不随页面筛选变化。仅管理员可访问这些文件。导出不含邀请码、会话令牌、管理员口令、图片二进制或私有原生状态。

0.2.2 对旧数据库采用增加字段的兼容升级，并在迁移前保存 SQLite 备份。已有邀请、协议和评分保留；协议创建版本与实际运行版本分别记录。

## 0.2.3 暂离记录

明确暂离保留同一attempt和原生进程；平均用时使用扣除暂离后的实际作答时间。CSV追加 `pause_count`、`paused_seconds`、`wall_elapsed_seconds`，JSON还包括逐次暂离区间和参与状态事件。旧的成绩和研究创建协议不修改，新的暂离规则作为 `pause_policy` 单独记录。暂离期间的题属于未评分，恢复后正常完成才进入正误和均值。

重新参与需要受试者主动确认；旧退出时间保存在参与事件详情中。服务重启导致内存盘面丢失时保留未评分记录，不伪造从原盘面恢复。直接断线仍按原计时规则处理。

## 0.2.4 新文本题的邀请预算

新增45道文本题（Singularity、OpenTTD、Enigma各15题）按每题原生上限100–360次决策分配，与本轮模型评测使用的任务预算一致；每题墙钟上限仍来自研究创建协议。新增邀请计划保存 `max_decisions` 与 `assignment_protocol=new-text45-task-native-v1`。旧邀请没有该覆盖字段，继续使用原研究的默认上限，不修改历史计划或成绩。

完整JSON和逐题CSV包含每道分配题的 `max_decisions`、`assignment_protocol`。统计仍以首个正式评分为单位；需要比较模型或不同人类条件时，应按这些逐题预算区分，不能把全体作答都视作原协议的100步。
