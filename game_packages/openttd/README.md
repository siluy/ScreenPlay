# OpenTTD 游戏包

第二个独立上游代码家族，采用 OpenTTD 15.3 的原生 Cocoa 界面和 OpenGFX 8.0 图形资源。上游提交固定为 14ec60f248547d4d062a1160f0fc26d742319888。来源见 [OpenTTD](https://github.com/OpenTTD/OpenTTD/tree/15.3)、[OpenGFX](https://github.com/OpenTTD/OpenGFX/tree/8.0)。

## 构建与运行

在项目根目录运行：

~~~sh
.venv/bin/gameworld fetch openttd
.venv/bin/gameworld build openttd
.venv/bin/gameworld run openttd-road-gap-1 --reference
.venv/bin/gameworld serve openttd-road-gap-2 --port 8788
~~~

当前已验证 macOS 原生构建。需要 Xcode Command Line Tools 和项目内的 CMake/Ninja；本机构建使用现有 PNG、LZMA、LZO 库。构建出的二进制依赖本机动态库，尚未作为可移植安装包发布。首次构建会从官方地址下载 OpenGFX，后续使用项目缓存。

配置、临时存档目录和遥测均位于该次运行的 private 目录。使用 OpenTTD 的 -c、-X、-x 参数固定配置目录并避免修改现有用户配置。声音和音乐关闭。源码保存在 .cache/sources，改动应用到 .cache/prepared，上游 checkout 保持干净。

## 保留的三个初始场景

| 任务 | 初始状态 | 成功条件 |
|---|---|---|
| openttd-dispatch | 道路完整，Inspection Bus 停在车库，两条订单已配置 | 启动同一辆巴士，使其停靠 West Stop 和 East Stop |
| openttd-road-gap-1 | 一处道路缺失，其余配置相同 | 修复标记道路，启动巴士并完成两个站点的停靠 |
| openttd-road-gap-2 | 两处道路缺失，其余配置相同 | 修复两处标记道路，启动巴士并完成两个站点的停靠 |

上述三个初始场景都以 50,000 英镑、零贷款开始，要求全过程现金不少于 45,000，不新增贷款，并保留原有巴士和两个站点。发车任务用于链路校准；两个修路任务是同一目标模板的场景变体，不代表两个不同游戏家族。

这里验证的是路线恢复与实际停靠，尚未实现煤矿货运或真实货物交付任务。参考操作由场景作者依据实际界面制作，不能当作模型自主轨迹或人类基线。

## 初态与时间

每次创建新进程，以固定种子生成 64×64 平坦地图，并使用原生游戏命令创建城镇、道路、车库、站点、巴士和订单。此阶段属于可信初始化，agent 接口中没有这些命令。

当前重置策略是重新构造固定场景，不是加载完整快照。已比较两次 road-gap-1 运行的地图尺寸、巴士位置/状态/ID、现金、断路数量和站点访问标记，初态一致。

模拟在等待 agent 时停止推进，UI 仍处理鼠标、菜单和绘制。普通输入后推进 8 次游戏状态更新；wait 按每 30 毫秒一次更新换算。所有推进都在私有控制通道内，agent 只能调用普通动作和 wait。游戏内快进可以减少真实等待时间，但不会增加一次动作获得的更新预算。

记录 processed_updates 与原生 native_tick 两个数值。如果玩家按下原生暂停按钮，允许的更新周期仍消耗预算，但 native_tick 可保持不变。这一差异会保留在轨迹的 simulation 字段中。最多 12,000 次更新的预算会在公开任务和剩余预算中显示，并在执行前截断到剩余额度。

## 评分

评分读取原生车辆的 last_station_visited、原有车辆/车站存在性、指定道路的实际连接方向、当前及最低现金和贷款记录。访问标记在每次原生游戏循环中更新，避免漏掉两次截图之间发生的停靠。

进展值只用于私有诊断。公开接口在任务结束前不提供道路缺口、车辆坐标、访问标记或部分奖励。只发车不修路的真实运行显示：巴士到达第一个站，但无法到达第二个站，最终得分为 0。

禁止切换游戏或加载另一个场景；运行中的模式切换会被拦截并记为违规。游戏控制台命令执行和作弊窗口在本游戏包中关闭。这些限制不代替操作系统隔离：当前仍在共享开发桌面运行。

## 修改范围

- [gameworld_bridge.cpp](native/gameworld_bridge.cpp)：固定场景、更新额度、原生状态导出和模式切换约束。
- [构建与插桩](../../src/gameworld/openttd_build.py)：原版源码准备、入口挂接、图形资源和编译。
- [环境适配器](../../src/gameworld/openttd.py)：进程生命周期、原生窗口截图、PyAutoGUI 输入、受控时间推进和评分。
- [场景与参考操作](tasks.json)：公开目标、规则、预算及建设者参考输入。

没有改写道路寻路、车辆行驶、站点停靠或玩家建造规则。初始化时跳过空地图不需要的产业生成告警。原生单线程模式用于协调本机 Cocoa 界面与受控游戏循环。

共用桌面执行器在鼠标移动后保留 80 毫秒，以便游戏处理指针进入菜单项，再发送点击/拖拽。此时序用于所有模型并记入运行元数据；不会自动查找或修正点击目标。

## 15 题课程扩展

当前任务集为 15 题，原有三个 ID 保留。难度为作者预估：easy、medium、hard 各 5，待人类及模型表现校准。每题 `parameters.curriculum` 记录机制和理由。旧三题保留 12,000 updates 预算；新增题 20,000 updates，为三站绕路和回库留出时间。难度不以等待次数定义。

新增机制包括：补充缺失站点订单、修正空站满载死锁、三站订单插入与重排、南侧 U 形绕路修复、完成巡检后停车及回库，以及现金余量更少的复合修复。原有相邻缺口题只是校准变体，不作为全部题目多样性的依据。所有任务仍是原生道路客车巡检，不能解释为真实客货运收入或交付测试。

`parameters.fixture` 是可信初始化参数；`parameters.goal` 是私有判分配置。桥接层使用原生建路、建站、造车和订单命令布置开局；模型只能从截图通过原生 GUI 操作。判分来自真实站点访问记录、道路位、原车身份、订单、停车/回库状态以及最低现金和是否借贷。构造工具和判分状态不向模型公开。

当前原生扩展已在 macOS 完成增量编译和 15/15 题真实桌面通关；每题均有非空 `reference.actions` 与成功运行目录。桌面录制由 `scripts/author_transport_gui.py` 经统一 Episode/PyAutoGUI 路径完成，并保存真实截图和私有状态。作者轨迹不是自主模型成绩。

显式订单与原生自动插入的灰色 implicit 记录分开判定：`orders` 只排除真正的 `OT_IMPLICIT`，其他显式非站点订单仍会使精确站点列表不匹配；`implicit_orders` 独立保留供审计。这不改变车辆停靠或原生调度规则。15 题现均有真实 PyAutoGUI 通关 reference，保留录制中的失败尝试；具体证据目录见每题 `reference.verified_run` 与 `artifacts/v1-transport-desktop.json`。三站回程产生 implicit Central 的真实轨迹验证了这一判分区别。
